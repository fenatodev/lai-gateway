# LAI Gateway 0.1.35 — technical alpha

This is a source-first technical alpha for local evaluation of `lai-gateway`.
It is not a hosted service, one-click installer, cloud runtime, browser agent,
n8n automation platform, general MCP tool executor, voice assistant, social
automation agent, or broad document/media processor.

## What is included

- Local Gateway and Workbench surfaces documented by `docs/quickstart.md`.
- Technical alpha readiness gate through `alpha-readiness/v1`.
- Release gate through `release-check` for version, branch, tag state and public
  caveats.
- Testable local identity binding for user/client/agent/service.
- Narrow non-dry-run authorization for `local_status.status` only.
- Single-use local authorization recovery grants for `local-status-read`.
- Local-model-first chat surface with explicit fallback and no cloud fallback.
- Local memory context with explicit write, scoped project/personal contexts and
  no authority grant.
- Restricted local document text for `.txt`, `.md` and `.json` under explicit
  workspace scope.
- Workbench document selection that lists metadata only and delegates inspection
  to the restricted reader.

## Required local validation

Before treating this as a usable alpha candidate, run from a clean checkout:

```bash
python3 -m lai_gateway --version
PYTHON=python3 make check
python3 -m lai_gateway release-check --target 0.1.35 --json
python3 -m lai_gateway alpha-readiness --target 0.1.35 --json
```

Expected gate state after PR102 is integrated and before publishing is
`release-check phase=ready_to_tag` and `alpha-readiness decision=candidate_go`.

## Explicit non-goals

This release does not enable browser authenticated sessions, n8n activation,
general MCP tool execution, agent-driven message sending, forms, applications,
purchases, public posting, credential use by an agent, broad PDF/OCR/Office
processing, or external automation. Those require their own specs, executor
containment, authorization evidence, negative tests and separate human approval.
